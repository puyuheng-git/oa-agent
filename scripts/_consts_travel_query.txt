OA 助手图：understand → (call_tool ⇄ human_handoff，可多步) → respond → remember。

可用 Tool 来自后台配置：已启用且校验通过的 Skill 声明的、已注册的 Tool。understand 由模型结合最近几轮对话与更早对话的
记忆理解员工意图：需要查 OA 数据时按 Skill 说明选 Tool 并填参，否则直接回答（日常聊天、通用问答；chat_mode=help 时
改为回复帮助）。模型不可用时回退到行程报销的内置规则；参数经 Tool 的 model_params 校验，身份字段一律丢弃，由服务端注入。

多步查询（引用式串联）：模型一次给出多个步骤，后面步骤的参数写成 {"$ref": "step1.list[0].id"}。模型看不到任何步骤的
返回值；call_tool 逐步执行，引用由服务端从前面步骤的返回字段白名单中取值，再按该 Tool 的参数规则校验。

模型看到的历史只含员工原话、聊天回复与查询摘要（工具、条件、记录 ID），不含业务明细，聊天回复不得编造业务数据。
超出历史轮数的旧对话由 remember 按发布配置压缩为记忆（截断 / 滚动摘要 / 要点提取，见 runtime.memory）。
LangGraph 只做编排：身份来自 RunContext（服务端会话），业务数据只来自 office-api 返回。
回复由 respond 节点按 Tool 配置的字段与名称确定性生成，模型不参与拼写业务数据。
上游暂时故障且发布配置 on_upstream_error=handoff 时，human_handoff 以 interrupt() 挂起等待管理员决定；
恢复后回到 call_tool 重新以员工身份调用当前步骤（身份在恢复时由服务端重新校验，不来自 Checkpoint）。
