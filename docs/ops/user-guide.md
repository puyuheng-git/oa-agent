# 使用说明

面向管理员、值班人员和 OA 对接人员。部署与运维见 [部署与运维手册](deployment.md)。

## 1. 入口一览

| 入口 | 地址 | 使用者 |
|------|------|--------|
| 管理后台 | `https://<Agent 域名>/admin/` | 管理员、值班人员 |
| 员工助手 | OA 页面右下角气泡（见 §4.1）；或 OA 菜单里的整页助手 | 员工（只能从 OA 进入） |
| 企业微信助手 | 企业微信里与智能机器人**单聊**（见 §4.2） | 员工（身份由 OA 按企微绑定解析） |
| 安装向导 | `https://<Agent 域名>/setup/` | 仅首次安装，装完永久关闭 |
| 健康检查 | `https://<Agent 域名>/healthz`、`/readyz` | 运维监控 |

上线验收建议：

1. 员工登录 OA，点右下角气泡，问“本月未报销的行程”，看到本人数据。
2. 管理后台“运行记录”中能看到这条运行及其时间线；“审计日志”中有该员工的 `chat.launch` 记录。
3. 在“Tool 管理”停用列表 Tool，员工再问会提示“该功能暂未开放”；重新启用即恢复。
4. 在“流程配置”修改“列表默认条数”，保存 → 校验 → 发布，再回滚到上一版本。
5. 如流程配置为“转人工介入”：office-api 故障期间员工提问会收到“已转人工处理”，恢复后在“介入中心”点“恢复执行”，员工页约 5 秒内显示结果。

## 2. 员工对话

- 员工只能从 OA 内的助手页进入（OA 服务端签发一次性身份断言），直接打开对话地址会提示“请从 OA 进入”。
- 只能查询**本人**的数据。内置行程报销查询，如“查上周的行程报销”“本月未报销的行程”“查看报销单 12345 的详情”；管理员在后台新增的 Skill 会出现在欢迎页（名称 + 示例问题）。身份以 OA 断言为准，消息里自称他人无效。
- 会话 30 分钟有效、自动续期；刷新页面需从 OA 重新进入。
- 上游故障且流程配置为“转人工”时，回复“已转人工处理”，页面会自动等待处理结果（最长约 35 分钟）。员工在此期间重新提问，旧的等待会被取消。

## 3. 管理后台页面

| 菜单 | 所需权限 | 用途 |
|------|----------|------|
| 运行总览 | `ops.run.view` | 成功率、P95、错误 Top、按日趋势、疑似卡住；无数据显示“暂无数据” |
| 运行记录 | `ops.run.view` | 按状态/员工/时间/错误码筛选；详情含事件时间线、失败节点、重试链路、介入任务 |
| 对话记录 | 查看 `ops.run.view_sensitive`，导出 `ops.conversation.export` | 按会话查看员工与助手的完整对话、模型调用原文；导出 JSONL 用于训练 |
| 介入中心 | `ops.intervention.handle` | 处理“转人工”任务：恢复执行或终止 |
| Tool 管理 | `ops.tool.manage` | 新建/编辑 Tool（office-api 只读接口）、从文件导入、启停、版本对比、激活版本 |
| Skill 管理 | `ops.skill.manage` | 新建/编辑 Skill（说明、填参指引、示例问题、可用 Tool）、从文件导入、启停 |
| 流程配置 | `ops.config.edit`（发布需 `ops.config.publish`，回滚需 `ops.config.rollback`） | 草稿 → 校验 → 发布 / 回滚 |
| 连接配置 | 查看 `sys.setting.view`，修改 `sys.setting.edit` | Redis、OA 对接、企业微信、运行参数 |
| LLM 配置 | 同上 | 提供方、模型、测试连接 |
| 账号 / 角色与权限 | `sys.account.manage` | 账号、角色、权限分配 |
| 审计日志 | `ops.audit.view` | 所有管理写操作的记录 |

所有写操作都要求填写或确认操作原因，并记入审计；同一操作重复提交只执行一次。

### 3.1 运行记录与运行操作

- 运行状态：运行中、等待人工、等待确认、成功、失败、超时、已请求取消、已取消、已过期。
- 事件时间线按顺序展示：员工输入 → 理解意图（意图、规则/模型解析、查询条件）→ 模型调用（发送内容、模型输出 JSON、Token）→ 调用业务接口（接口路径、参数、HTTP 状态、返回条数）→ 回复员工的内容；以及转人工、管理员操作（操作人、原因）和错误。内容为原文（只有 token、API Key、口令等密钥类会打码），单条超过 16000 字符截断；不展示模型推理过程。每条事件可展开“原始记录（JSON）”。有 `ops.run.view_sensitive` 权限时，详情页“会话”一栏有“查看完整对话”链接。

### 3.1.1 对话记录（完整对话与训练数据）

- 每次员工提问都会保存：员工原话、助手回复原文（含表格对应的结构化数据、转人工提示、错误提示），以及每次模型调用的完整输入（系统提示词 + 员工输入）和模型最终输出、Token。模型的推理过程不保存。
- 只有密钥类内容会打码；手机号、身份证等个人信息和业务数据**按原文保存**，请只把该权限授予必要人员。
- 列表按会话分组，可按员工、关键词、时间筛选；点开一行查看按时间顺序排列的完整对话。查看和导出都记入审计（`conversation.list` / `conversation.view` / `conversation.export`）。
- **导出 JSONL**：选好时间范围（最长 92 天，单次最多 5 万条消息）后点“导出 JSONL（训练用）”。每行一个会话：

```json
{"thread_id": "thr_…", "oa": "zhangsan", "channel": "web",
 "messages": [{"role": "user", "content": "本月未报销的行程", "run_id": "run_…", "created_at": "…"},
              {"role": "assistant", "content": "你在 … 共有 2 张…", "reply_type": "markdown", "data": {…}, "run_id": "run_…"}],
 "model_calls": [{"run_id": "run_…", "model": "…", "messages": [{"role": "system", "content": "…"}, {"role": "human", "content": "…"}],
                  "output_text": "{\"tool\": \"query_my_travel_expense_list\", \"args\": {…}}", "parsed": {…}, "usage": {…}, "status": "ok"}]}
```

- 对话记录不随事件保留期清理，需要清理时由 DBA 按时间删除 `agent_conversation_message`、`agent_model_call_log`。
- 只有本功能上线（迁移 `0007`）之后的对话才有记录。
- “取消运行”（需 `ops.run.operate`）：执行中的运行在下一个步骤开始前停止；等待中的运行立即取消，相关介入任务一并关闭。
- “重试”（需 `ops.run.operate`）：仅失败/超时的运行可重试，用**原员工的会话**重新执行原消息，生成一条新运行并与原运行互相链接。员工会话已过期时无法重试。结果不会推送到员工页面，员工重新提问即可。

### 3.2 介入中心

只有当流程配置“上游故障处理 = 转人工介入”，且 office-api 出现超时、不可用或 5xx 时，才会产生介入任务。

- 打开任务后，系统实时检查是否可恢复，并列出不可恢复的原因：员工会话已过期、运行不再等待人工（如已被员工的新消息取代或已取消）、流程版本已不一致、检查点缺失等。
- **恢复执行**：以员工本人的身份重新调用一次业务系统，结果写回该运行，员工页自动显示。
- **终止运行**：运行标记为失败（`HUMAN_TERMINATED`），员工页提示稍后重新提问。
- 同一任务只能被处理一次；两位管理员同时处理时，后提交者会收到“任务已被处理或版本已变化，请刷新”。
- 任务默认 30 分钟未处理即过期（运行参数可调），运行记为失败（`INTERVENTION_EXPIRED`）。
- “员工确认”类任务只能由员工本人确认，管理员不能代办（相关业务写接口待 OA 提供后启用）。

### 3.3 Tool 管理

一个 Tool 就是 office-api 的一个 **GET 只读查询接口**。在后台新建/编辑后立即对员工对话生效，不需要改代码或发版。仓库里的 `openapi/*.yaml` 只在首次启动时导入一次，之后以后台为准。

**新建 Tool**（“新建 Tool”按钮）需填写：

| 区域 | 字段 | 说明 |
|------|------|------|
| 基本信息 | Tool 名 | 小写字母/数字/下划线，创建后不可改，如 `query_my_leave_list` |
| | 名称说明、用途说明 | 用途说明是给模型看的：什么问题该用它、能查到什么 |
| | 业务上游 | 在「系统设置 → OA 对接」分别配置**签发地址**与**业务上游**目录（标识、名称、基址；域名不写死）。新建 Tool 时选择上游标识；**前提：该上游认同签发入口发出的员工 Authorization**，且各接口仍做业务授权。被 Tool 使用的上游不能删除；改上游属于不兼容变更 |
| | 接口路径 | 所选地址下的相对路径，如 `/hr/leave/index`；只支持 GET，不能填域名 |
| 身份与传参 | 注入员工身份 | 开启后服务端把当前员工 `oa` 写进 JSON 参数；模型或客户端给的 `oa` 一律丢弃，参数表里不能出现 `oa` |
| | JSON 参数字段 | 如 `queryParams`：非“顶层”参数打包成 JSON 放进这个查询参数；留空则所有参数直接作为查询参数（此时不能注入身份） |
| | 身份查询参数 | 如 `user_id`：接口用普通查询参数传员工身份时填写，服务端写入当前员工 `oa`，模型无法指定。**前提：office-api 会按 token 校验该值**，否则不要这样配置 |
| 模型可填的参数 | 参数名、显示名、类型（文本/整数，文本可选“日期”）、必填、可选值、最小/最大、默认值、说明、顶层 | 可选值写成 `0=未报销, 1=已报销`，名称用于回复里描述查询条件；超过最大值会被截断到最大值 |
| 返回结果 | 结果类型（列表/单条）、字段、显示名称、列表中显示 | 只有列出的字段会返回给员工（白名单）。列表按勾选的列出表格（未勾选默认前 6 个字段）；单条记录只显示设置了显示名称的字段 |
| 变更原因 | | 写入审计 |

- **编辑**（列表或详情里的“编辑”）：兼容变更（加可选参数、改显示名称、放宽限制、加返回字段）立即生效；不兼容变更（删参数、新增必填、收紧可选值或上下限、改路径、改身份注入、删返回字段）保存为“待激活”版本，在详情中“激活”后才生效。
- **从 Apipost 导入**（推荐，省去手填）：
  1. 在 Apipost 打开接口文档，复制分享链接（形如 `https://docs.apipost.net/docs/detail/xxxx?target_id=yyyy`）。
  2. 点“从 Apipost 导入”，粘贴链接，按需勾选“用 LLM 补全…”（需已配置默认模型），点“解析”。
  3. 解析结果自动填进“新建 Tool”表单，顶部黄色提示列出需要核对的地方（例如：识别为身份参数、必填参数、未导入的路径/请求头参数、已排除的凭据字段、未配置 LLM 等），逐项检查后填写变更原因并保存。
  4. 开了 LLM 时会附带一个配套 Skill 草稿，可在表单底部修改，保存 Tool 后自动创建（取消勾选则不创建）。
  - 限制：只支持 `docs.apipost.net` 的公开分享链接，不支持设了访问密码的文档；只导入 GET 接口；`auth_key`、`token`、`secret` 之类字段不会进入返回白名单。导入本身只生成草稿，不改动任何 Tool，但会记一条审计。
- **从文件导入**：批量导入 `openapi/*.yaml`，同名 Tool 会被文件内容覆盖为新版本（同样遵守兼容/不兼容规则）；文件解析失败时保留最后有效版本。
- **未注册**的常见原因：已停用、规范中未启用、高风险或需确认、非 GET、没有有效版本；列表悬停可见具体原因。
- **停用**立即生效：新运行和进行中的运行再调用该 Tool 都会被拒绝。
- **版本对比 / 激活**：在详情抽屉中选择两个版本查看字段级差异，可激活待激活版本或回退到历史版本。

### 3.4 Skill 管理

Skill 是面向员工的一组能力。员工提问时，模型会看到**所有可用 Skill** 的说明和填参指引，从它们的 Tool 中选一个并填参数。

| 字段 | 说明 |
|------|------|
| Skill 名 | 小写字母/数字/下划线，创建后不可改 |
| 显示名称 | 员工欢迎页显示的功能名，也用于回复标题，如“请假查询” |
| 说明 | 解决什么问题；模型据此判断何时使用（必填） |
| 填参指引 | 告诉模型如何把员工的话转成参数，如“『上个月』换算为具体日期；年假对应 leave_type=1” |
| 示例问题 | 每行一条，最多 10 条，显示在员工欢迎页并可一键提问 |
| 可用 Tool | 从已有 Tool 中多选 |

- Skill 停用、或它的某个 Tool 未注册时，该 Skill 校验不通过，对话不再使用它；**所有** Skill 都不可用时员工会收到“该功能暂未开放”，不会调用业务系统。
- **重要**：新增的 Tool 只能靠模型选择。未配置 LLM（或流程配置为“仅规则”）时只有内置的行程报销查询可用。
- 新增一个查询能力的完整步骤：① OA 侧确认 office-api 有该员工可调的只读接口（按员工 token 只返回本人数据）；② 新建 Tool；③ 新建 Skill 并选中该 Tool；④ 员工重新打开助手即可在欢迎页看到。

### 3.4.1 从旧版本升级

已有部署的 Tool/Skill 数据不会被自动改写。升级后如需新的显示名称、示例问题等，在 Tool 管理、Skill 管理分别点“从文件导入”一次（行程报销的 Tool 会生成一个兼容的新版本，立即生效）。流程配置中的“帮助回复”如保留旧文本会继续使用，清空后按可用 Skill 自动生成。

### 3.5 流程配置

| 配置项 | 说明 |
|--------|------|
| 意图解析方式 | 自动（有可用模型用模型，失败回退规则）/ 仅规则 |
| 指定模型 | 留空用默认模型（带 `intent` 用途标签的优先） |
| 列表默认条数 | 1～20，员工未说明条数时使用 |
| 上游故障处理 | 直接失败 / 转人工介入 |
| 帮助回复 | 员工问“你能做什么”或问题与所有 Skill 无关时的回复；留空则按可用 Skill 的名称、说明、示例自动生成 |

操作流程：

1. “基于当前版本新建草稿”，修改后“保存草稿”。
2. “校验”：服务端检查取值范围、模型是否存在且启用。页面上的提示只是预检，以服务端结果为准。可用 Skill 不在流程配置里选，由“Skill 管理”的启停决定。
3. “发布”：只有已校验且校验后未再修改的草稿能发布；发布时填写原因。新运行立即使用新版本，**进行中的运行仍按启动时的版本执行**。
4. “回滚到此版本”：生成一条新的发布记录指向历史版本；已发布版本永远不可修改。

每条运行详情都显示它绑定的“配置发布”ID，便于追溯。

## 4. OA 对接说明（给 OA 开发）

1. **OA 宿主页**（服务端）构造断言 `{oa, uid, display_name, exp(≤60 秒), nonce, iss:"oa-host", aud:"oa-langgraph"}`，JSON 做 base64url（去掉 `=`）后，用“OA assertion HMAC 密钥”做 HMAC-SHA256，得到 `<body>.<hex 签名>`。
2. 宿主页**服务端**调用 `POST {Agent}/v1/chat/launch`，body `{"assertion": "..."}`，得到 `launch_code`（60 秒、一次性）。
3. 页面输出 `<iframe src="{Agent}/chat/?launch={launch_code}">`。Agent 后台“允许嵌入的 OA 域名”必须包含宿主页的协议+域名。
4. Agent 用 `AGENT_GATEWAY_SECRET` 调 office-api `POST /agent/token/mint`（表单 `oa`、`gateway_secret`）为该员工换取 token，之后以该 token 调用业务接口；token 只存在服务端，不下发浏览器。

5. **业务接口的提示语会展示给员工**：响应 `{code, msg, data}` 中的 `msg`（也认 `message`、`errMsg`）按下面规则处理，所以请写成员工能看懂的话，不要放 SQL、堆栈或内部信息。
   - `code` 不是成功码（如参数校验不通过）：员工看到「业务系统提示：{msg}」。
   - HTTP 4xx 且带 `msg`：同上；HTTP 5xx 不展示 `msg`，只提示「业务系统暂时不可用」。
   - 成功但没有数据：直接显示 `msg`（如「暂无未接收合同」），代替默认的「没有查到…记录」。
   - 成功且有数据：表格下方附「业务系统提示：{msg}」。
   - `成功`、`操作成功`、`获取成功`、`ok`、`success` 这类通用词不展示。提示语会去掉 HTML 标签、遮盖疑似密钥，最长 200 字。

字段要求、错误码与 PHP 5.2 参考写法见 `docs/design/2026-10-09-oa-service-side-design.md` §3.3。

### 4.1 悬浮挂件嵌入（推荐，类似 Dify 的 embed 脚本）

在 OA 任意页面（如公共页脚模板）粘贴：

```html
<script>
  window.oaAgentConfig = {
    hostUrl: '/general/ds/agent/assistant_host.php?mode=embed'  // 必填：OA 自己的宿主地址
    // title: 'OA 智能助手', primaryColor: '#1C64F2',
    // width: '24rem', height: '40rem', right: '1rem', bottom: '1rem'
  }
</script>
<script src="https://<Agent 域名>/embed.js" charset="utf-8" defer></script>
```

- 页面右下角出现气泡，点开是对话窗口；窗口右上角 ↻ 重新连接、× 关闭；手机宽度（≤640px）全屏。
- 也可以用样式覆盖：`#oa-agent-bubble-button { background-color: ... !important; }`、`#oa-agent-bubble-window { width: ... !important; height: ... !important; }`。
- **配置里没有、也不能有员工身份或密钥。** 与 Dify 在前端传 `user_id` 不同：前端参数可被任意伪造，本系统身份只认 OA 服务端签发的断言（硬约束：模型/客户端自报的 `oa` 一律丢弃）。
- 首次点开气泡时，挂件 iframe 打开 `hostUrl`（同 OA 域名，自动带上 OA 登录 Cookie）。`assistant_host.php?mode=embed` 的约定：校验 OA 登录（未登录返回提示）→ 按上面第 1、2 步签断言、换 `launch_code` → **302 跳转**到 `{Agent}/chat/?launch={launch_code}&embed=1`（`embed=1` 时对话页不显示自身页头）。
- `charset="utf-8"` 必须保留：OA 页面是 GBK，脚本里的中文需按 UTF-8 解码（Agent 也会在响应头声明 UTF-8）。
- Agent 后台“允许嵌入的 OA 域名”必须包含 OA 的协议+域名。
- 会话过期后窗口内会提示“点窗口右上角 ↻ 重新连接”。

### 4.2 企业微信智能机器人（长连接）

**一次性配置**

1. 企业微信管理后台 → 智能机器人（建议由**企业超级管理员**创建，否则消息里的 userid 是加密值，OA 可能匹配不到绑定）→ 开启「API 模式」并选择「**长连接**」→ 复制 **BotID** 和 **Secret**。
2. Agent 管理后台 → 连接配置 → 「企业微信」页填写 BotID、Secret，保存。约 10 秒内自动连接，页面顶部显示「长连接状态：已连接」（点「刷新」更新）。清空 BotID 或 Secret 即断开。
3. OA 开发需让**签发入口** `/agent/token/mint` 支持按 `wework_user_id` 签发（见 `docs/design/2026-10-09-oa-service-side-design.md` §3.4；入口宜挂中性域名，不必绑 office-api）。未完成前员工发消息会收到「暂时无法确认你的 OA 身份」。

**员工使用**：在企业微信里打开机器人单聊直接提问（如「查上周的行程报销」）。机器人先回「正在查询…」，查完更新为结果（表格为 Markdown）。首次进入会话会收到可用功能和示例。

**规则与限制**

- 只支持单聊；群里 @ 机器人会回复「请在单聊中向我提问」，避免个人数据被群成员看到。
- 支持文字和语音（转文字）；图片、文件等提示只支持文字。
- 身份只认 OA 解析出的主账号，消息里自称他人无效；未绑定时把 OA 的提示（如「你的企业微信尚未绑定 OA 账号」）回给员工。
- 运行记录、对话记录中渠道显示为 `wecom`；限流、去重、转人工、重试与 OA 内助手一致。转人工的结果企业微信不会主动推送，员工需稍后重新提问。
- 同一机器人只能有一个长连接：**只部署一个 Agent 实例**。若状态显示「同一机器人在别处建立了新连接，本连接已被替换」，说明有另一个程序（或另一套环境）用同一 BotID 连上了，请停掉多余的那个；本实例 5 分钟后自动重试。
- 企业微信限制：每个会话发消息 30 条/分钟、1000 条/小时。

## 5. 常见问答

- **为什么总览里 Token / 成本显示“暂无数据”？** 未配置 LLM 或模型未返回用量时如实显示，不估算。
- **为什么有的运行标“疑似卡住”？** 运行中超过阈值（默认 30 秒）但未到超时（默认 60 秒），仅提示，不改变状态。
- **管理员能看到模型的推理过程吗？** 不能。只展示步骤、耗时、错误码与摘要。
- **能在后台直接改运行状态或检查点吗？** 不能。只能通过取消、重试、介入恢复/终止这些受控操作，且都有审计。
