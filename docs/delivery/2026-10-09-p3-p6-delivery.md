## 1. 功能

### P3 人工介入

- 介入任务 `agent_intervention_task`：类型 `admin`（上游故障转人工）与 `user_confirm`（员工确认，模型已就绪）；状态 pending → resolving → resolved / cancelled / expired；乐观版本锁防并发重复处理。
- 流程图新增 `human_handoff` 节点：流程配置“上游故障处理 = 转人工”时，office-api 超时 / 不可用 / 5xx 触发 LangGraph `interrupt`，运行进入 `waiting_human`，检查点保留现场。
- 恢复：重新校验任务状态、运行状态、流程版本、发布记录、员工会话（只存会话引用，不存 token）、检查点中断点，任一不满足则如实列出原因并拒绝；通过后以员工本人身份 `Command(resume)` 重新执行。重复恢复返回 409，不会再次调用业务系统。
- 终止、取消（执行中运行在下一步骤前停止；等待中立即取消）、重试（失败/超时运行用原员工会话重新执行，生成新运行并链接 `parent_run_id`）。
- 员工新消息会取代同会话中等待人工的旧运行（`RUN_SUPERSEDED`）。
- 介入任务过期巡检（默认 30 分钟，运行参数可调）。
- 确认令牌模型 `confirmation.issue / verify_and_consume`：只存哈希、一次性、绑定员工与载荷；管理员调用确认类任务返回 403 `ADMIN_CANNOT_CONFIRM` 并审计。
- 员工端：转人工后自动轮询 `GET /v1/chat/runs/{run_id}`（仅本人），处理完成后原消息替换为结果。
- 后台：介入中心页（列表/筛选/待处理数、可恢复判定与原因、恢复/终止）；运行详情增加取消、重试、介入任务、重试链路。

### P4 Tool / Skill

- 从 `openapi/*.yaml` 同步 Tool：解析校验（身份字段不得作为模型参数、必须声明结果字段、超时范围等）、版本化存储、字段级兼容性比较（unchanged / compatible / breaking）。兼容变更自动生效；不兼容变更存为待激活版本；解析失败保留最后有效版本。
- 注册条件：启用 + 规范启用 + 有有效版本 + 高风险必须要求确认；不满足则不注册并给出原因。
- 停用即拒绝调用：运行时通过实时注册表代理，进行中的运行也立即生效。
- Skill（`skills/*.yaml`）注册与校验：依赖 Tool 未注册或 Skill 停用时，对话直接返回“该功能暂未开放”，不调用业务系统。
- 后台：Tool 管理（同步报告、启停、版本列表、版本对比、激活）、Skill 管理（同步、启停、依赖状态）。

### P5 配置版本

- `agent_definition / agent_workflow_version / agent_config_release`：草稿 → 服务端校验 → 发布（必须携带已校验内容的哈希）→ 回滚（生成新发布记录）。已发布版本不可修改。
- 每次运行绑定启动时的 `config_release_id`；发布/回滚不影响进行中和等待中的运行（恢复时用原版本）。
- 可配置项：意图解析方式、指定模型、列表默认条数、上游故障处理、帮助回复、依赖 Skill。
- 后台：流程配置页（表单编辑、本地预检 + 服务端校验、差异对比、发布、回滚、已发布版本、发布记录）。

### P6 加固

- 权限矩阵测试：枚举全部管理接口，验证无权限账号一律 403。
- 所有管理写接口：缺 CSRF → 403，缺 `Idempotency-Key` → 拒绝；同一幂等键只执行一次。
- 事件保留清理（每小时，按保留天数分批删除）。
- 运行超时与“疑似卡住”改为按本段执行计时（见 §8 修复记录）。
- 部署与运维手册、使用说明、演示与端到端自检脚本、启动脚本（Windows / Linux）。

## 4. API 说明

| 接口 | 权限 | 说明 |
|------|------|------|
| `GET /v1/chat/runs/{run_id}` | 员工 ticket | 本人运行的状态与结果（他人 404） |
| `POST /v1/admin/runs/{id}/cancel`、`/retry` | `ops.run.operate` | body `{reason}` |
| `GET /v1/admin/interventions`、`/{id}` | `ops.intervention.handle` | 列表（status/kind/run_id 筛选、pending_count）、详情（resumable / terminable 及原因） |
| `POST /v1/admin/interventions/{id}/resume`、`/terminate` | `ops.intervention.handle` | body `{reason, version}`；不可恢复 409 `NOT_RECOVERABLE`；确认类 403 `ADMIN_CANNOT_CONFIRM` |
| `GET /v1/admin/tools`、`/{name}`、`/{name}/versions/{no}`、`/{name}/diff?from_no&to_no` | `ops.tool.manage` | 注册表、版本、差异 |
| `POST /v1/admin/tools/sync`、`/{name}/enable`、`/disable`、`/activate` | `ops.tool.manage` | 启停 body `{reason}`；激活 `{version_no, reason}` |
| `GET /v1/admin/skills`、`/{name}`；`POST /sync`、`/{name}/enable`、`/disable` | `ops.skill.manage` | |
| `GET /v1/admin/workflows`、`/{wf}`、`/{wf}/schema`、`/{wf}/diff?from_no&to` | `ops.config.edit` | `to` 为版本号或 `draft` |
| `PUT /{wf}/draft`、`DELETE /{wf}/draft`、`POST /{wf}/draft/validate` | `ops.config.edit` | |
| `POST /{wf}/publish` | `ops.config.publish` | body `{content_hash, reason}`；未校验 409 `NOT_VALIDATED` |
| `POST /{wf}/rollback` | `ops.config.rollback` | body `{version_no, reason}` |
| `GET /readyz` | 公开 | 新增 `agent`：已注册 Tool、Skill 状态、当前发布版本 |

管理写接口统一要求：权限点 + `X-CSRF-Token` + `Idempotency-Key` + 审计（审计与变更同事务，审计失败则操作失败）。

## 5. 权限与安全

- 管理员与员工两套主体：恢复/重试使用员工自己的会话，管理员身份只记录为操作人；管理员不能代员工确认业务操作。
- 后台不能直改运行状态或检查点，只有取消/重试/恢复/终止四种受控操作，均经状态机 CAS 迁移并审计。
- 介入上下文只保存会话引用（ticket 哈希键），不保存员工 token；office token 仍只在服务端。
- 模型输出不参与权限判定；业务数据只来自 office-api 以员工 token 返回的结果。
- 停用 Tool / Skill 立即在运行时生效；不兼容的接口变更不会自动上线。
- 配置发布必须基于已校验内容的哈希，防止“校验后又被改”。
- 密钥只写不读、日志与审计脱敏，沿用 P0 机制。
