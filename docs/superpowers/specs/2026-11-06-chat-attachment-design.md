| 项 | 内容 |
|----|------|

| 范围 | 员工在对话中上传文件并交给模型阅读；与导出文件共用登记和文件管理 |

### 已锁定决断

| ID | 选择 | 含义 |
|----|------|------|
| **D1** | 引用进记录，字节不进记录 | 对话记录和 Checkpoint 只存文件引用。模型能看到的正文和图片都从引用在请求时生成 |
| **D2** | 整段会话目录 | 该会话里已发送的上传，之后每一轮都出现在目录里，不受 `history_turns` 限制。正文历史仍按原规则压缩 |
| **D3** | 先读懂再回答 | 小文件整份进入模型。大文件先给覆盖全文件的结构，再由内置工具按范围读完相关部分。读文件不走 MCP，也不占用 `max_tool_steps` |
| **D4** | 同一张登记表 | `origin = upload \| export`。文件管理用来源区分。OSS 配齐走 OSS，否则落本地 |
| **D5** | 附件配额独立 | 正文仍受 `message_max_chars` 限制。附件按个数和字节另计，不占这 2000 字 |

## 1. 目标

员工可以一次上传多个文件，让模型按文件内容回答。截图可以粘贴进对话框，按图片处理。已发送的上传出现在管理端「文件管理」，与助手导出的文件区分开。

验收：

1. 选择文件、拖进对话区域、粘贴截图，未发送前只在浏览器里，文件管理看不到。
2. 发送后模型能读到小文件的全文；大文件能看到每一张表或全部页的结构，并按问题继续读。
3. 员工只能下载自己的上传。管理员列表和下载仍走 `ops.file.view`，并记审计。
4. 类型、大小、个数不合法时整批不落盘，正文也不发送。

---

## 2. 非目标

- OCR、语音、压缩包、`.doc`、`.xlsm`、可执行文件。
- DeepSeek Files API、按 DeepSeek 公式重算视觉 token。供应商 usage 没有视觉 token 时，界面显示「未返回」。
- 把服务器路径、OSS 对象键或预签名 URL 交给模型或浏览器。
- 自动删除、管理员删除、员工撤回已发送文件。无引用的对象 v1 不回收。
- 欢迎页技能列表里出现「读附件」。不使用 `sys.fs_read`，不把文件放进沙箱目录。
- 企微通道上传。本期只做员工对话页。

---

## 3. 员工侧交互

未发送的文件只留在浏览器。点发送时：

1. 保证当前会话存在。
2. 整批上传。有一个不合法，整批失败，输入框里的字和文件都保留。
3. 上传成功后调用现有发送接口，正文与 `attachment_ids` 并列。只有附件、没有正文，允许发送。每个 `file_id` 必须属于当前员工和当前会话，且尚未写入消息；写入成功后不能再挂到另一条消息。

三条入口同一套校验：

- 选择文件。
- 拖进对话区域（消息列表和输入区）。
- 对话框内粘贴。剪贴板里的 png、jpeg、webp、gif 成为附件，不把 base64 写进输入框。纯文字仍贴进输入框。图片和文字都有时，图片成为附件，文字贴进输入框。

配额：

| 项 | 值 |
|----|----|
| 单次个数 | 5 |
| 单文件大小 | 20MB，空文件拒绝 |
| 图片 | png、jpeg、webp、gif |
| 文档 | xlsx、xls、docx、pdf、md、csv |

扩展名和文件头都要符合。`.csv` / `.md` 没有固定文件头：须能按 UTF-8 或 GBK 解码，且不含 NUL。Office 文档解压后超过 50MB，或压缩条目超过 2000，整批拒绝。图片单边超过 8192 像素，或总像素超过 6400 万，整批拒绝。

员工提示用语：

| 情况 | 提示 |
|------|------|
| 类型或文件头不符 | 只能上传 Excel、Word、PDF、Markdown、CSV，以及 png、jpeg、webp、gif 图片 |
| 超过 5 个 | 一次最多 5 个文件 |
| 超过 20MB | 单个文件不能超过 20MB |
| 空文件 | 文件是空的 |

重复消息拦截只比较非空正文。正文为空的附件消息不参与这 300 秒拦截。

## 4. 登记、存储、下载

继续用 `agent_export_file`。新迁移增加列，不改已发布的 `0012_export_file`。

| 列 | 说明 |
|----|------|
| `origin` | `upload` 或 `export`。旧行视为 `export` |
| `sha256` | 上传对象的内容哈希。导出旧行可空 |
| `media_kind` | `image` 或 `document`。导出旧行可空 |
| `in_message` | 上传在消息写入成功后为真。导出恒为真。文件管理和模型目录只看为真的行 |

`file_id` 使用 `upl_` + ULID。`ticket` 列仍非空且唯一，上传行写入不可猜测的内部值。`/v1/chat/exports/{ticket}` 只接受 `origin = export`，上传票据不能换成下载。

对象键只存相对路径：`{oss.prefix}/attachments/v1/objects/{sha256前2位}/{sha256}`。禁止完整 URL。同一份上传字节只存一个对象，每个员工一行登记。导出文件保持现有键，不与上传对象合并。

接口响应、模型提示、审计详情都不含 `object_key`。模型句柄只有文件名和哈希前 8 位。

员工下载：`GET /v1/chat/files/{file_id}`，须当前会话，`oa` 必须与登记行一致，且 `in_message` 为真。否则 404「文件不存在」。可重复下载。对话气泡只显示文件名、大小和引用；刷新后的图片用该接口取字节，在浏览器里预览。

管理端沿用 `/v1/admin/export-files`。列表增加 `origin`、`media_kind`，并支持按来源筛选。打开列表和下载继续审计，审计失败则请求失败。权限点仍是 `ops.file.view`。

上传接口使用员工会话凭证，不走管理端 CSRF。发送仍带现有 `client_msg_id`：同一编号重试不重复写入引用，也不再跑一遍模型。

消息写入成功前登记行 `in_message` 为假。写入失败留下的对象 v1 不删除，文件管理不展示。

## 5. 模型如何读文件

当前图在工具执行完后不再把结果交回模型。因此读文件走单独的阅读循环：不进入办公查询的工具链，也不占用 `max_tool_steps`（默认 3，上限 5）和「表格最多行数」（默认 50）。

`sys.attachment_read` 由运行时注入。它不出现在欢迎页技能里，管理员不能靠关掉某个 Skill 把它关掉，也不写入 `BUILTIN_CATALOG`。参数里的路径、URL 一律忽略。只接受本租户、本员工、本会话、且 `in_message` 为真的 `file_id`。

阅读循环本身不调用办公 Tool，也不占用 `max_tool_steps`。同一会话里员工改问业务时，仍走原来的 understand → call_tool。模型看到目录后可以只回答文件，也可以把这一轮交给办公工具链。

每一轮都准备目录。整份内容放得进下文的送入余量时，同一次模型调用带上目录、全文和图片。放不下时，这一次只带目录：

- 文件编号、文件名、类型、大小、哈希前 8 位。
- 表格：每张表的列名、行数；数值列给计数与合计。
- PDF：页数；有目录则给目录。
- Word / Markdown：标题大纲。
- 图片：宽高。
- 加密的 Excel、Word、PDF：该文件标「已加密，无法读取」，同批其他文件照常。
- 扫描版 PDF 抽不出文字层：标「没有可提取的文字」。

结构摘要最长 8000 字。超出时保留每张表的表名和行数，列名按表截断并注明已截断。

送入预算：模型上没有上下文字段，v1 使用固定余量。抽出的文本一次最多 3 万字，图片一次最多 8 张。能放进这个余量的，第一次模型调用就带上全文和图片。放不下的，只带目录，再由工具按范围读。

图片发给模型前：按 EXIF 旋转，转到 sRGB，去掉位置等元数据。长边不超过 2048 的不缩小。超过的把长边缩到 2048。动图只把第一帧发给模型，员工下载仍是原文件。图片部分使用 `image_url` 的 base64。

单次工具读取上限：表格最多 200 行，PDF 最多连续 3 页，Word / Markdown / CSV 最多 8000 字。读完把结果交回模型。模型给出最终回答就停止；它要求继续读，且还有未读内容，就再读一次。没有更多可读内容，或本轮已读 20 次，就用已经读到的内容写回答。这一轮上下文放不下更早的片段时，收成一行「已读过：表名，第几行到第几行」或「已读过：第几页到第几页」。回答里写上实际读过的范围。回答长度仍受「聊天回复最大字数」（默认 4000）约束。

抽出的文本按不可信数据围栏送入模型，并经过现有 `prompt_guard`。标志只记事件，不参与权限判定。

失败：

| 情况 | 行为 |
|------|------|
| 对象不存在，或字节与 `sha256` 不符 | 整次请求失败。员工看到「附件已损坏或无法读取，请重新上传」。不改成空内容重试 |
| 模型拒绝图片 | 整次请求失败。员工看到「当前模型无法查看图片」。不改成空内容重试 |

用量只记录供应商返回的 usage。没有视觉 token 时不估算。

目录保存在图状态的独立列表里，`remember` 压缩正文历史时不裁这张列表。超过 `history_turns` 的旧上传仍在目录中。抽出的正文和图片不写入长期记忆。

## 6. 接口

员工：

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/v1/chat/attachments` | `multipart` 文件字段。成功返回 `file_id`、文件名、大小、`media_kind`。此时 `in_message` 为假 |
| POST | `/v1/chat/messages` 与 `/messages/stream` | 增加 `attachment_ids`（最多 5 个）。`message` 可为空字符串，但二者不能同时空 |
| GET | `/v1/chat/files/{file_id}` | 本人下载已发送的上传 |

管理端列表增加查询参数 `origin`，取值 `upload` 或 `export`。缺省为全部。

## 7. 实现落点

| 仓库 | 落点 |
|------|------|
| `oa-agent-chat` | 选择、拖拽、粘贴；发送前整批上传；气泡展示与带凭证预览 |
| `oa-langGraph` | 上传、下载、迁移、存储键、阅读循环、`sys.attachment_read`、文件管理的来源列和筛选 |

读文件的库：图片用 Pillow；`.xlsx` 用 openpyxl；`.xls` 用 xlrd；`.docx` 用 python-docx；`.pdf` 用 pypdf。不执行宏，不计算公式，单元格按文件里已存的值读出。

## 8. 测试

自动化要覆盖：

- 类型、文件头、空文件、超过 5 个、超过 20MB、Office 解压超限：整批不落盘，且不产生已发送消息。
- 员工只能下载自己的、已发送的上传；他人 `file_id`、未发送的 `file_id`、上传票据走导出接口，均为「文件不存在」。
- 管理端可按来源筛选；列表和下载有审计记录。
- 两名员工上传同一份字节：两行登记，一个对象。
- 小文件的全文出现在模型输入里。大表的目录包含每一张表的列名和行数。回答包含读过的范围。
- 加密文件标成无法读取，同批其他文件仍进入目录。
- 对象缺失或哈希不符时请求失败，且没有第二次空内容调用。
- 超过 `history_turns` 的上传仍在目录里。带附件时正文长度仍只受 `message_max_chars` 限制。

对话页的拖拽和粘贴用前端测试覆盖分类结果。浏览器里真实粘贴截图、OSS 上传，在交付说明里标为手工或外部依赖，不把未执行写成通过。
